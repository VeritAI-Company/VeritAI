# VeritAI 프론트엔드 기능과 기술

## 1. 프론트 흐름과 담당 범위

```
크롬 확장(웹페이지 img·video) · PWA(카메라·갤러리·영상 장면) · 안드로이드 앱(갤러리·공유·영상 장면)
  → 사진 준비: 긴 변 1280px · JPEG 0.92 (PWA는 EXIF 방향 보정, 앱은 영상 프레임 추출)
  → POST /api/detections (file + analysisMode=face_crop_only + clientType + ownerToken)
  ← 202 Accepted + requestId (재사용 가능한 완료 결과는 200으로 즉시 반환)
                          ↓ 결과 조회: 300ms → ×1.25 → 최대 2s, retryAfterMs 반영, 최대 3분
       확장: GET /api/detections/status?ids=... (진행 중인 여러 검사를 한 번에)
       PWA·앱: GET /api/detections/{requestId}
                          ↓
  결과 확인: cnn.modelLoaded · isValidResult → 실패면 오류로 표시
  → 화면 표시: 배지 · 결과창 · 판정 이유 · 얼굴 박스 · Grad-CAM 히트맵
```

프론트는 백엔드 API만 호출하고 AI 서버는 직접 호출하지 않는다. 판정 기준, 표시 문구, 요청 규칙은 공용 코드 `shared/`에 두고 확장과 PWA가 함께 쓴다. 앱은 Expo 빌드 구조상 `mobile/` 밖을 가져올 수 없어 복사본을 두며, 웹과 값이 같은지 단위 테스트가 검사한다. 세 채널은 같은 사진을 같은 입력(1280px, JPEG 0.92)으로 보내고 같은 기준으로 표시한다.

## 2. 프론트엔드 기능과 기술

### ★ F1. 크롬 확장: 웹페이지 위 실시간 검사

- **기술**　Chrome Extension Manifest V3, Vite 5 (content script 단일 파일 빌드), Service Worker, Offscreen Document와 `OffscreenCanvas`, Shadow DOM, `MutationObserver`, `IntersectionObserver`, `declarativeNetRequest`
- **검사 진입**　사진 위 "검사" 버튼, 자동 검사(화면에 30% 이상 보이고 300ms 유지된 사진), 우클릭 메뉴(`contextMenus`), 파일이나 다른 페이지 사진 끌어다 놓기, 영상은 현재 프레임을 Canvas로 캡처한다.
- **사진 수집**　content script가 백그라운드에 요청하면 Offscreen Document가 사진을 받아 `OffscreenCanvas`로 1280px, JPEG 0.92로 줄인다. 실패하면 백그라운드가 다시 받는다. 1280px 이하의 JPEG, PNG, WebP 원본은 재압축하지 않고 그대로 보낸다. 실패 응답, `text/*`·JSON 형식(오류 페이지), 15MB 초과, 15초 초과는 거부한다.
- **외부 링크 차단 대응**　디시인사이드처럼 Referer가 없는 요청을 403으로 막는 사이트를 위해, 사진을 받는 동안만 `declarativeNetRequest` 세션 규칙으로 확장 자신의 요청(`initiatorDomains`=확장 ID)에 원래 페이지 origin을 Referer로 붙이고, 끝나면 규칙을 지운다. 사용자의 일반 페이지 요청은 건드리지 않는다.
- **동시성과 캐시**　동시 검사는 `hardwareConcurrency`가 4 이하면 2개, 아니면 3개다. 자동 모드에서는 화면 안에 있고 면적이 큰 사진부터 보낸다. 결과는 LRU 캐시 200개에 두어 같은 사진을 다시 보내지 않고, 밀려난 캡처 이미지(blob URL)는 해제한다.

| 장치 | 구현과 효과 |
|---|---|
| Shadow DOM 격리 | 배지(`veritai-host`)와 결과창(`veritai-report-host`)을 Shadow DOM 안에 넣고 `:host { all: initial }`로 페이지 상속 스타일을 끊는다. 사이트의 태그 규칙(`button`, `canvas` 등)이 결과창에 섞이지 않는다. |
| 겹친 사진 처리 | `elementsFromPoint`로 화면 맨 위 사진에만 버튼을 붙이고, 가려진 사진의 버튼은 숨긴다. 다른 사진과 겹치지 않는 사진은 가려짐 확인을 건너뛰어 계산을 줄인다. |
| 나눠 붙이기 | 버튼 붙이기를 큐에 모아 한 번에 12ms까지만 처리하고 브라우저에 차례를 넘긴다. 사진 400장 페이지의 가장 긴 멈춤이 1,177~3,387ms에서 0~54ms로 줄었다. |
| 변경 감시 | `MutationObserver` 변경을 150ms 단위로 모으되 최대 500ms마다 반드시 처리한다. 계속 바뀌는 페이지에서도 새 사진을 놓치지 않는다. |
| 광고 판별 | 확실한 광고(`adsbygoogle`, `google_ads` 등)는 제외한다. `banner`·`promo`·`sponsor` 영역은 사진 위 4단계까지만 확인하고, 자동 검사만 빼고 버튼은 붙인다. |
| 클릭 처리 | 클릭 지점에 VeritAI 요소가 있을 때만 위치를 계산한다. 결과창이나 모달 위 클릭이 아래 사진 버튼으로 새지 않게 한다. |
| 원상 복구 | 버튼 배치를 위해 바꾼 부모의 `position`을 기록해 두었다가 전원을 끄면 되돌린다. 확장 업데이트로 연결이 끊긴 탭은 3초마다 감지해 화면을 정리한다. |

### ★ F2. 결과 리포트와 판단 근거 시각화

- **기술**　Canvas 2D, 공용 판정 코드 `shared/judgment.js`, 공용 히트맵 코드 `shared/heatmap.js`
- **판정 표시**　`confidence`를 조작 확률 막대로 보여 주고 판정 기준 50%를 함께 표시한다. 얼굴별 확률은 50% 이상 빨강, 30% 이상 주황, 30% 미만 초록이다. 얼굴은 찾았지만 확률이 없으면 "판정 없음"으로 표시한다. 인식 신뢰도 50% 미만 얼굴은 목록에서 처음에 접어 둔다.
- **판정 이유**　AI 응답의 `decisionReason`을 사람이 읽는 문장으로 바꾼다. 응답 형식이 달라도 `result`와 `result.cnn` 양쪽에서 값을 찾는다.

| `decisionReason` | 표시 |
|---|---|
| `high_single_face_probability` | 한 얼굴에서 강한 조작 흔적이 보였습니다 (가장 높은 얼굴 N%) |
| `high_average_face_probability` | 여러 얼굴에서 전반적으로 조작 흔적이 보였습니다 (얼굴 평균 N%) |
| `below_combined_thresholds` | 한 얼굴이 N%였지만 단독 기준(80%)보다 낮고, 평균도 N%라 정상으로 판정 (가장 높은 얼굴이 50% 이상일 때만) |
| `full_image_*` | 얼굴 0개면 "얼굴을 찾지 못해 사진 전체로 판정", 찾은 얼굴이 모두 화질 낮음(`quality.label`이 `poor`)이면 "모두 화질이 낮아 분석에서 제외하고 사진 전체로 판정", 그 밖에는 "얼굴 영역을 읽지 못해 사진 전체로 판정". 모두 참고용 |

- **히트맵**　응답의 `cnn.views[].cam` 숫자 그리드(Grad-CAM)를 영역 bbox에 맞춰 Canvas에 그린다. 영역 안 상위 20% 칸만 칠하고, 최대값의 30% 미만은 칠하지 않으며, 색이 잘 보이도록 사진을 최대 40% 어둡게 깐다. 영역 탭(사진 전체, 얼굴별)과 진하기 슬라이더, 원본 보기를 제공한다. 첫 탭은 AI가 판정에 실제로 쓴 영역(`winningView`)이다. 숫자 그리드가 없는 예전 응답은 `heatmapBase64` 이미지를 겹쳐 그린다.
- **오해 방지**　히트맵 진하기는 영역 안에서 모델이 많이 반응한 위치일 뿐 사진끼리 비교하는 값이 아니므로, 영역 확률과 함께 "진하기는 사진끼리 비교하는 값이 아닙니다" 안내를 표시한다.
- **오답 신고**　`POST /api/feedback`으로 `requestId`, `reportedAt`, `reason`을 보낸다. 한글 입력기의 조합 중 Enter(`isComposing`)는 제출로 보지 않아 마지막 글자가 빠지지 않는다.
- **앱에서 재사용**　앱은 PWA 리포트 화면(`?embed=report`)을 `react-native-webview`로 띄우고 `postMessage`로 결과와 사진을 넘긴다. PWA는 `window.ReactNativeWebView`가 있을 때만, 보낸 창(`event.source`)이 없는 메시지만, 사진은 `data:image/` 주소만 받는다. 10초 안에 결과가 없으면 안내를 띄운다.

### ★ F3. PWA와 안드로이드 앱

- **PWA 기술**　Vite 5, `vite-plugin-pwa`(Workbox, `autoUpdate`), Vanilla JS
- **PWA 기능**　카메라 촬영(`capture="environment"`)과 갤러리 선택을 지원한다. 갤러리에서 영상을 고르면 브라우저에서 영상을 열어 장면 한 장만 사진으로 뽑아 보내고(`portal/video.js`, 영상은 서버로 보내지 않으며 `mediaType: video_frame`), 슬라이더와 ±1초, ±5초 버튼으로 장면을 고른다. `createImageBitmap(file, { imageOrientation: 'from-image' })`로 휴대폰 사진의 방향(EXIF)을 바로잡은 뒤 1280px, JPEG 0.92로 다시 압축한다. 홈 화면 설치와 오프라인 열기를 지원한다. 개발 서버에서는 Service Worker를 끄고, 예전에 등록된 것이 있으면 자동으로 해제해 오래된 화면이 남지 않게 한다.
- **앱 기술**　Expo SDK 57, React Native 0.86, React 19, `expo-share-intent`, `expo-image-picker`, `expo-image-manipulator`, `expo-video-thumbnails`, `react-native-webview`, AsyncStorage
- **앱 기능**　다른 앱의 "공유 → VeritAI"로 사진과 영상을 받는다. SNS 링크가 공유되면 스크린샷 방법을 안내한다. 영상은 `expo-video-thumbnails`로 원하는 시점의 프레임을 추출하고 시간 막대(끌거나 눌러서 이동, `FrameSlider`, 새 네이티브 모듈 없이 `PanResponder`로 구현), ±1초, ±5초, 처음·1/4·절반·3/4 지점으로 장면을 고른다. 공유받은 영상도 영상 길이를 읽어 같은 화면을 쓴다. 최근 기록은 사진 없이 판정 결과만 50개까지 남긴다.

| 공용 파일 | 역할 | 앱 복사본 |
|---|---|---|
| `shared/judgment.js` | 판정 기준값, 색, 판정 설명과 이유 문구, 결과 형식 검사, 확률 표시 | `mobile/src/judgment.js` |
| `shared/api.js` | 분석 모드, 시간 제한, 조회 간격, 다시 시도 기준, 압축 기준, 서버 상태 문구 | `mobile/src/api.js` 안에 같은 값 |
| `shared/records.js` | 소유자 토큰 생성, 서버 기록 삭제 순서 | `mobile/src/records.js` |
| `shared/heatmap.js` | 히트맵 영역 선택, 그리기, 안내 문구 | 없음 (앱은 PWA 리포트를 띄움) |

### ★ F4. 결과 신뢰성: 잘못된 결과를 정상으로 보여 주지 않기

- **AI 판정 실패**　모델 로딩이나 추론에 실패하면 서버는 `cnn.modelLoaded=false`와 함께 `confidence=0`, `isDeepfake=false`를 채워 보낸다. 프론트는 이를 "AI 판정 실패"로 표시하고 다시 시도할 수 있게 하며, 결과 캐시, 오늘 통계, 앱 최근 기록에 넣지 않는다. 30분 안에 실패가 있었으면 서버 상태에 "최근 AI 판정 실패"를 표시한다.
- **형식 검사**　`isValidResult`가 `isDeepfake`(또는 `deepfake`)가 참·거짓(문자열 `"true"`/`"false"` 허용)이고 `confidence`가 유한한 숫자인지 확인한다. 아니면 "분석 결과를 읽을 수 없습니다"로 처리해, 빈 응답이 "정상 0%"로 보이는 것을 막는다.
- **확률 표시**　`formatPercent`는 0~1로 자른 뒤 버림으로 표시하고, 부동소수점 오차(0.29×100=28.999...)는 1e-9를 더해 보정한다. 판정 기준 50% 바로 아래인 0.4996이 반올림으로 "50.0%, 정상"으로 보이던 모순을 "49.9%"로 해결했다. 막대 폭은 `percentWidth`로 따로 계산한다. 얼굴별 확률, 판정 이유 문장, 사진 위 배지는 소수 첫째 자리까지 보여 준다 (기준값 80%와 인식 신뢰도는 정수).
- **입력 통일**　세 채널의 재압축 기준을 `UPLOAD_MAX_SIDE=1280`, `UPLOAD_IMAGE_TYPE=image/jpeg`, `UPLOAD_IMAGE_QUALITY=0.92`로 통일했다. 짧은 변이 `MIN_IMAGE_SIDE=80`px 미만인 사진과 영상 화면은 PWA와 앱에서 서버에 보내기 전에 거절한다 (확장은 화면에서 80x80 미만 사진을 건너뜀).

| 채널 | 이전 | 현재 |
|---|---|---|
| 확장 사진 | WebP 0.92 | JPEG 0.92 (1280px 이하 원본은 그대로) |
| 확장 영상 프레임 | WebP 0.7 | JPEG 0.92 |
| PWA | WebP 0.85 | JPEG 0.92 |
| 앱 | JPEG 0.85 | JPEG 0.92 |

### ★ F5. 네트워크 복구와 내 기록 삭제

| 장치 | 구현과 효과 |
|---|---|
| 점진적 조회 간격 | 300ms에서 시작해 1.25배씩 늘려 최대 2초 간격으로 묻는다. 응답의 `retryAfterMs`가 있으면 300ms~2s 안에서 따른다. 결과가 나오면 다시 300ms로 돌아간다. |
| 일괄 조회 (확장) | 진행 중인 검사 번호를 모아 `GET /api/detections/status?ids=...` 한 번으로 묻는다. 사진 여러 장을 동시에 검사해도 요청 수가 늘지 않는다. |
| 선택적 다시 시도 | 연결 실패, 응답 읽기 실패, 408, 429, 5xx는 연속 3번까지 2초 뒤 다시 묻는다. 404(서버 재시작으로 기록 없음) 등 나머지 4xx는 바로 실패로 처리한다. 전체 대기는 3분이다. |
| 시간 제한 | 업로드와 단건 조회는 20초, 서버 상태 확인은 4초다. 확장의 상태 조회가 늦으면 그 회차만 건너뛰고 다시 묻는다. |
| 저장 경쟁 방지 | 검사 번호 저장은 Promise 큐로 한 번에 하나씩 처리한다. 오늘 통계는 백그라운드 한 곳에서 순서대로 더해 동시 검사와 여러 탭에서도 빠지지 않는다. |

- **소유자 토큰**　채널마다 처음 검사할 때 `crypto.getRandomValues`로 32바이트(64자리 16진수) 토큰을 만든다. 확장은 `chrome.storage`, PWA는 `localStorage`, 앱은 AsyncStorage에 저장하고 검사할 때 `ownerToken`으로 함께 보낸다. 삭제할 때는 `X-VeritAI-Owner-Token` 헤더로 보내 이 기기의 기록만 지울 수 있다.
- **삭제 순서**　서버가 돌려준 검사 번호를 최대 500개까지 저장해 둔다. 삭제는 100개씩 묶어 `DELETE /api/detections`로 보내고, 묶음이 거절(403, 404, 409)되면 4개씩 동시에 단건 `DELETE`로 다시 지운다. 404(이미 없음)와 403(내 것이 아님)은 정리된 것으로 보고, 409(처리 중)는 남겨 다음에 지운다. 연결이 실패하면 저장 목록을 그대로 둔다.
- **확장의 캐시 비우기**　서버 삭제가 성공했을 때만 메모리 캐시와 화면 표시를 지우고, `chrome.storage` 변경으로 다른 탭에도 알려 함께 정리한다. 서버 삭제는 한 번만 하고 오늘 통계는 유지한다.
