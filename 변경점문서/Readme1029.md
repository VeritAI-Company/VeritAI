# 히트맵 총정리

---

# 1. 히트맵이란
- AI가 "조작 의심"이라고 판단할 때 사진의 어느 부분을 근거로 삼았는지 색으로 표시한 그림
- 빨강에 가까울수록 판단에 크게 쓰인 곳
- 판정 결과를 바꾸지 않음. 이미 나온 판정의 이유를 보여주는 설명용 자료 (XAI, 설명 가능한 AI)
- 주의: "조작된 부분"을 정확히 오려내는 기능이 아님. "모델이 판단할 때 많이 본 곳"이라는 뜻

---

# 2. 전체 흐름

```
[사진]
  │
  ▼
AI 서버 (ai/main.py, ai/cnn.py)
  1. 얼굴 검출 → 얼굴 위치(bbox) 목록
  2. 검사 화면(view) 만들기 : full(사진 전체) + face_1, face_2 ... (얼굴만 잘라낸 것)
  3. 화면마다 EfficientNet-B4로 조작 확률 계산 + Grad-CAM 히트맵 계산
  4. 최종 확률 = 화면들 중 가장 높은 확률, 0.5 이상이면 조작 의심
  │
  ▼
백엔드 (Spring)
  - AI 응답의 cnn 값을 그대로 전달 (가공하지 않음, 백엔드 수정 없음)
  - DB 저장 용량이 넘칠 때만 저장본에서 cnn, heatmapBase64를 뺌 (화면 응답과 무관)
  │
  ▼
화면 (크롬 확장 / PWA / 앱)
  - cnn.views[].cam 숫자 표를 받아 원본 사진의 해당 위치에 색으로 덧그림
  - 앱은 결과 상세를 PWA 화면(?embed=report)으로 띄우므로 PWA와 같은 히트맵이 나옴
```

---

# 3. AI가 히트맵을 만드는 원리

## 3-1. 모델 구조 (간단히)
- EfficientNet-B4는 사진을 여러 블록으로 거치면서 점점 작은 격자로 요약한다.
  - 입력 사진 → … → 5번 블록 출력 14x14 격자 → … → 마지막 출력 7x7 격자 → 평균 → 진짜/가짜 점수
- 격자의 한 칸은 사진의 한 구역이다. 14x14면 사진을 가로세로 14칸으로 나눈 것
- 판정은 항상 마지막 7x7까지 계산해서 나온다. 모델 구조라서 뺄 수 없다.
- 히트맵은 중간의 14x14 격자로 그린다. 7x7로 그리는 건 Grad-CAM이 실패했을 때의 대체용뿐이다.

## 3-2. CAM (예전 방식, 7x7, 지금은 대체용)
- 마지막 7x7 격자의 칸 값 × "가짜" 분류 가중치를 더해 칸마다 점수를 냄
- 장점: 빠르고 단순함
- 단점: 칸이 너무 커서 한 칸에 눈과 배경이 같이 들어감 → 얼굴 옆 배경까지 빨갛게 보이기 쉬움

## 3-3. Grad-CAM (현재 방식, 14x14)
- 5번 블록의 14x14 격자에서 "이 값이 조금 변하면 가짜 점수가 얼마나 변하나"(기울기)를 계산
- 기울기가 큰 특징일수록 중요하다고 보고, 그 가중치로 칸마다 점수를 냄
- 장점: 칸이 4배 촘촘해서 위치가 더 정확함
- 앞부분은 기울기 없이 실행하고 5번 블록 뒤쪽만 기울기를 계산해서 속도 부담이 작음
- 모델 가중치는 고정(requires_grad=False), 학습 상태는 바뀌지 않음
- 판정 확률은 CAM과 완전히 같음 (PC에서 차이 0.0 확인)
- Grad-CAM이 실패하면 자동으로 CAM으로 대체하고 이유를 `heatmapError`에 남김

## 3-4. 숫자 표로 만드는 과정 (`cam_to_grid`)
1. 음수는 0으로 (조작 쪽 근거만 남김)
2. 그 화면 안에서 가장 큰 값을 1로 맞춤
3. 그 화면의 조작 확률을 곱함 (확률이 낮은 화면의 값은 작게 전달)
4. 소수 셋째 자리로 반올림해서 전송

- 화면 쪽에서는 이 값을 다시 영역별로 맞춰서 그린다 (5장). 확률이 낮다는 정보는 탭의 %와 안내 문구로 보여준다.

# 4. 응답 데이터 형식

```json
"cnn": {
  "fakeProbability": 0.91,
  "isDeepfake": true,
  "threshold": 0.5,
  "heatmapView": "face_1",
  "heatmapMethod": "gradcam",
  "views": [
    { "name": "full",   "fakeProbability": 0.12, "bbox": null,
      "cam": [[0.0, 0.01, ...], ...] },
    { "name": "face_1", "fakeProbability": 0.91, "bbox": {"x": 120, "y": 80, "w": 160, "h": 160},
      "cam": [[0.0, 0.35, ...], ...] }
  ]
},
"heatmapBase64": "..."
```

| 필드 | 뜻 |
|---|---|
| `views[].name` | 화면 이름. `full` = 사진 전체, `face_N` = N번째 얼굴 |
| `views[].fakeProbability` | 그 화면의 조작 확률 |
| `views[].bbox` | 그 화면이 원본 사진에서 차지하는 위치 (full은 null) |
| `views[].cam` | 히트맵 숫자 표 (14x14, 값 0~1, 조작 확률이 곱해진 값) |
| `heatmapView` | 처음에 보여줄 화면 (확률이 가장 높은 화면) |
| `heatmapMethod` | `gradcam` 또는 `cam` |
| `heatmapError` | Grad-CAM이 실패해 CAM으로 대체했을 때만 생김 (이유) |
| `heatmapBase64` | 예전 화면용 그림 (확률 1위 화면, JPG). 예전 버전 호환용 |

- 좌표 기준: AI가 가로 최대 1280px로 줄인 사진 기준. 화면도 같은 기준으로 그림

# 5. 화면에서 그리는 방식 (`drawCamGrid`)

크롬 확장(`frontend/content.js`)과 PWA(`portal/main.js`)가 같은 방식, 같은 기준 값을 쓴다.

1. 영역별로 다시 맞춤
   - 그 영역에서 가장 강한 칸을 기준(1)으로 다시 계산 → 확률이 낮은 얼굴도 가장 강한 곳은 빨강
2. 상위 20%만 칠함
   - 영역 안의 칸을 값이 큰 순서로 세워서 위 20% 칸만 칠하고 나머지는 투명
   - 상위 20%라도 가장 강한 곳의 30%보다 약하면 칠하지 않음
   - AI가 얼굴 전체를 고르게 봤더라도 그중 특히 많이 본 곳만 남김
3. 색과 진하기
   - 연한 주황 → 빨강 (피부색과 겹치는 노랑은 쓰지 않음)
   - 약한 곳은 연하게, 강한 곳은 진하게 (투명도 곡선)
4. 사진을 살짝 어둡게
   - 색이 피부색에 묻히지 않도록 사진 전체를 어둡게 깔고 그 위에 색을 올림
   - 슬라이더에 따라 같이 변하고, 눈 버튼(원본 보기)을 누르면 원래 밝기
5. 부드럽게 늘리기
   - 14x14 표를 두 단계로 늘리고 가장자리만 살짝 흐리게 해서 계단 모양을 없앰
   - 아이폰 사파리는 흐림 기능이 없어 부드럽게 늘리기만 함
6. 얼굴 영역 점선 네모 (`drawViewOutline`)
   - 지금 탭의 히트맵을 계산한 얼굴 영역을 파란 점선으로 표시
7. 예전 서버 응답(cam 없이 heatmapBase64만 있음)은 예전 방식 그림으로 표시

# 6. 화면에서 보는 법

## 6-1. 크롬 확장
1. 사진의 검사 배지를 눌러 결과창 열기
2. "판단 근거 보기" 버튼 → 히트맵 화면으로 전환 ("얼굴 위치 보기"로 되돌아감)
3. 제목: "히트맵 · 얼굴 1 기준"처럼 지금 보는 영역
4. 사진 위
   - 파란 점선 네모: 히트맵을 계산한 얼굴 영역
   - 주황~빨강: AI가 많이 본 곳, 빨강일수록 가장 많이 본 곳
5. 슬라이더: 히트맵 진하기 (기본 85), 눈 버튼: 원본 사진만 보기
6. 탭: `얼굴 1 87.0%`, `얼굴 2 8.0%`처럼 영역 이름과 그 영역의 조작 확률
   - 처음엔 확률이 가장 높은 영역이 선택됨
   - 얼굴이 많으면 화면에 표시 중인 얼굴만 탭으로 나옴
   - 사진 전체 확률이 1% 미만이면 사진 전체 탭은 숨김
7. 안내 문구
   - 기본: "얼굴 1 영역의 조작 확률 87.0% 기준입니다. 이 영역 안에서 색이 진할수록 판단에 크게 기여한 곳입니다."
   - 확률 30% 미만: "조작 근거가 약한 영역이라 히트맵은 참고용입니다." 추가
   - 확률 1% 미만: "이 영역에서는 조작 근거를 찾지 못해 표시할 색이 없습니다." 추가
8. 범례: "약함 → 강함" 색 막대

## 6-2. PWA / 앱
- 결과 화면의 "판단 근거 보기" → 같은 탭, 점선 네모, 슬라이더, 안내 문구, 범례

## 6-3. 읽을 때 주의
- 색은 그 영역 안에서의 상대적인 강도다. 확률이 낮은 영역도 가장 강한 곳은 빨강으로 나온다.
- 근거가 얼마나 강한지는 색이 아니라 탭의 %와 안내 문구로 판단한다.

# 7. 코드 위치

## 7-1. AI (`ai/`)

| 위치 | 하는 일 |
|---|---|
| `cnn.py` `HEATMAP_METHOD`, `GRADCAM_LAYER_INDEX` | 방식, 층 설정 |
| `cnn.py` `build_cnn_views_bgr` | full + 얼굴별 화면 만들기 |
| `cnn.py` `_forward_gradcam` | Grad-CAM 계산 |
| `cnn.py` `_forward_cam` | 예전 CAM 계산 (대체용) |
| `cnn.py` `cam_to_grid` | 숫자 표로 변환 (정규화 × 확률) |
| `cnn.py` `cam_to_color_image` | 예전 그림(JET 색) 만들기 |
| `cnn.py` `predict_views` | 위 과정을 묶어 결과 반환 |
| `main.py` `run_cnn_prediction` | cnn 결과를 받아 얼굴별 확률 연결 |
| `main.py` (응답 만드는 부분) | `heatmap_array` → `heatmapBase64`(JPG) 변환 |

| `frontend/content.js` `drawViewOutline` | 얼굴 영역 점선 네모 |

| `portal/main.js` `camViews`, `defaultCamView`, `drawCamGrid`, `drawViewOutline`, `renderHeatmapPanel` | PWA 같은 기능 |
| `portal/index.html`, `portal/style.css` `.heatmap-legend` | PWA 슬라이더, 범례 |

# 8. 자주 묻는 질문

- 탭이 하나뿐이다
  - 얼굴을 찾지 못한 사진(사진 전체 탭만 있음)이거나, 사진 전체 확률이 1% 미만이라 숨겨진 경우
- 확률이 낮은데 빨갛게 나온다
  - 정상. 색은 그 영역 안에서 상대적으로 많이 본 곳. 근거가 약하다는 건 탭 %와 "참고용" 문구로 확인
- 히트맵이 아예 안 보인다
  - 그 영역 확률이 0%에 가까우면 칠할 근거가 없어서 색이 없음
- 얼굴 전체가 아니라 몇 군데만 칠해진다
  - 상위 20%만 칠하도록 해서 정상
- 핸드폰과 PC 결과가 조금 다르다
  - 업로드 전 이미지 크기 조정, 압축 차이 때문에 조금 다를 수 있음
